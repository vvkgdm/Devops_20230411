ALBIC:
ALBIC triggers the creation of an Application Load Balancer (ALB) and necessary supporting AWS resources whenever an Ingress resource in created on the cluster with anootation as below
kubernetes.io/ingress.class:alb

It  acts as the Ingress service in the K8s. Where we can re-direct the traffic using the conetxt paths. But if we use Application Load balancer (ALB) Ingress Controller [ALBIC]. 
WE can spin up the application load balancer in the AWS and it will act as the Ingress in the K8s world.

It supports 2 traffic modes --Ip and instances
Instance mode:
Register node with you cluster as targest for ALB
Traffic reaching the ALB is routed through NODE PORT of your service and then proxied to your pods
This is default traffic mode
IP mode:
Register Pods as the targets for ALB
Traffic reaching top ALB directly routed to Pods
to use this we need to mention annotations as below
alb.ingress.kubernetes.io/target-type:ip

ALBIC creation prequistes:
We need to create the IAM ROles with Policy ARN and create service account in the k8s and bound them together 
WE need deploy AWS Loadbalancer Controller using the Helm3 which is a pre-requiste for the ALBIC

eksctl create cluster --name=eksdemo1 --region=us-east-1 --zones=us-east-1a,us-east-1b --without-nodegroup 

eksctl create nodegroup --cluster=eksdemo1 --region=us-east-1 --name=eksdemo1-ng-private1 --node-type=t3.medium --nodes-min=2 --nodes-max=4 --node-volume-size=20 --ssh-access --ssh-public-key=kube-demo --managed --asg-access --external-dns-access --full-ecr-access --appmesh-access --alb-ingress-access --node-private-networking       

Associating the roles to the cluster
eksctl utils associate-iam-oidc-provider --region us-east-1 --cluster eksdemo1 --approve

Download the IAM policy for aws loadbalancer from kubernetes and create the policy in aws using  that file
curl -o iam_policy_latest.json https://raw.githubusercontent.com/kubernetes-sigs/aws-load-balancer-controller/main/docs/install/iam_policy.json
aws iam create-policy --policy-name AWSLoadBalancerControllerIAMPolicy --policy-document file://iam_policy_latest.json
Take ARN from that
"Arn": "arn:aws:iam::625253134850:policy/AWSLoadBalancerControllerIAMPolicy

We're creating the new ROLE and attaching newly created policy to that role Also we're creating service accountin k8's and attachin new role created with new service account. 
It will work in AWS only 

eksctl create iamserviceaccount   --cluster=eksdemo1 --namespace=kube-system --name=aws-load-balancer-controller --attach-policy-arn=arn:aws:iam::625253134850:policy/AWSLoadBalancerControllerIAMPolicy --override-existing-serviceaccounts --approve

Install the AWS Load Balancer Controller using Helm V3. 
We're creating deploymnts services of aws-load-balancer-controller. Cauwse when we create the Ingress manifest file. It will create the ALB in AWS using the service account associated to the deployements and services we're creating usiong the helm

helm repo add eks https://aws.github.io/eks-charts
helm repo update

helm install aws-load-balancer-controller eks/aws-load-balancer-controller \
  -n kube-system \
  --set clusterName=eksdemo1 \
  --set serviceAccount.create=false \
  --set serviceAccount.name=aws-load-balancer-controller \
  --set region=us-east-1 \
  --set vpcId=vpc-0165a396e41e292a3 \
  --set image.repository=602401143452.dkr.ecr.us-east-1.amazonaws.com/amazon/aws-load-balancer-controller
